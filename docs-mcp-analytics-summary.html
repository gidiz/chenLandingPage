1️⃣ חיבור Google Analytics ל-MCP

הבעיה: כלי ה-GA4 בשרת ה-MCP נכשלו עם insufficient authentication scopes.

האבחון: שני ליקויים נמצאו:

  1. ה-service account לא היה מצורף לחשבון ה-Google Analytics (GTM כן היה מחובר).
  2. תהליך ה-MCP ב-VS Code לא קלט את קובץ ה-.env ונפל להרשאות gcloud ישנות בלי scopes.

התיקון:

  1. ה-service account צורף כ-Viewer בחשבון ה-GA4 (Admin ← Account Access Management).
  2. נוסף טוען .env מובנה לשרת ה-MCP (server/mcp/index.ts) — השרת קורא את ההרשאות בעצמו, בלי תלות ב-VS Code.

תוצאה: ✅ ga4_list_accounts / ga4_list_properties / ga4_run_report עובדים דרך ה-MCP.

2️⃣ הרחבת ה-MCP עם כלי כתיבה ל-GTM

שרת ה-MCP הורחב מכלי קריאה בלבד לכלים הבאים:

  • gtm_list_triggers / gtm_list_variables / gtm_get_tag — קריאה מורחבת
  • gtm_create_tag / gtm_update_tag — יצירה ועדכון תגים
  • gtm_create_trigger / gtm_create_variable — טריגרים ומשתנים
  • gtm_create_version — יצירת גרסת container מה-workspace (ללא פרסום)
  • gtm_deploy_version_to_environment — פריסה ל-environments מותאמים בלבד (Development)

הרשאות שניתנו ל-service account

GTM — AccountUser
GTM — Container (drchenpardo.co.il)Publish (כוללת Edit + Approve)
Google Analytics — AccountViewer (כלי ה-GA4 הם קריאה בלבד)
הגנה כפולה על Live: (1) ה-OAuth scope של tagmanager.publish לא נכלל בכוונה — Google חוסמת פרסום ל-Live ברמת ה-token. (2) כלי הפריסה בודק את סוג ה-environment ומסרב ל-Live ול-Latest בקוד.

3️⃣ תיקון האנליטיקס בפרודקשן (Vercel)

הממצא המרכזי: נכס ה-Prod ב-GA4 היה ריק לחלוטין. בדיקת האתר החי גילתה:

gaMeasurementId: "", gtmContainerId: "", appEnvironment: "local"

ה-GTM בכלל לא נטען בפרודקשן — אפס אנליטיקס באתר החי.

שורש הבעיה: משתני הסביבה ב-Vercel היו קיימים אבל ריקים (מסוג Sensitive, ולכן קשה היה לראות זאת). הבילד נאפה עם ערכים ריקים.
