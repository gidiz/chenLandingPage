2. Agents מומלצים — לפי סדר עדיפות

Frontend Security Agent — סוקר אבטחה צד-לקוח עדיפות 1נבנה · #6

למה: ה-QA Agent בודק build וסטנדרטים, לא אבטחה צד-לקוח. באתר יש v-html (PageHero, TreatmentInfoSection), הזרקות JSON-LD דרך innerHTML, GTM/GA4 ו-YouTube embeds — ואין security headers ב-nuxt.config.ts.

תחומי אחריות:

  • קריאה בלבד — פולט Security Verdict: PASS / FAIL שמשתלב ב-loopback
  • v-html חדש, JSON-LD escaping (< → \u003c), סודות ב-bundle (רק NUXT_PUBLIC_*)
  • rel="noopener noreferrer", PII ב-dataLayer, origins של סקריפטים חיצוניים
  • המלצת CSP / security headers דרך routeRules

קובץ: .github/agents/frontend-security-agent.agent.md · כלים: read, search

Backend Security Agent — סוקר אבטחה צד-שרת עדיפות 1נבנה · #7

למה: ממצאים פתוחים מתוכנית 003 (CSRF על /api/chat, RLS על ה-RPC), ולידציה ידנית במקום zod, וכלי כתיבה ב-MCP (gtm_create_*, gtm_deploy_version_to_environment) בניגוד לכלל "MCP read-only".

תחומי אחריות:

  • קריאה בלבד + npm audit --omit=dev, mcp:typecheck, build
  • zod בגבול ה-route, MAX_MESSAGE_LENGTH/MAX_HISTORY_ITEMS כגבולות אבטחה, rate limiting
  • חשיפת SUPABASE_SERVICE_ROLE_KEY/OPENAI_API_KEY, צורת שגיאות, אין console.*
  • CHAT_REPLY_DISCLAIMER (הסרה = Critical), prompt injection, timeouts, SQL/RLS, כלי MCP כותבים

קובץ: .github/agents/backend-security-agent.agent.md · כלים: read, search, execute

Content Agent — קופירייטר רפואי בעברית עדיפות 1נבנה · #8

למה: האתר תוכן-כבד. ב-server/db/content/chen-treatment-notes.json יש טיפולים עם title/subtitle ריקים (skin-booster, mesotherapy), ה-FAQ, דפי הטיפולים (suitability / process / expectations) ושדות seoTitle/seoDescription בקטלוג — אף Agent לא אחראי עליהם.

תחומי אחריות:

  • כתיבה בעברית בלשון נקבה עקבית ("מתאים למי שהעור שלה…")
  • ניסוח שמרני ורגולטורי — בלי "מבטיח", "ללא סיכון", "תוצאות מובטחות"
  • התאמה למונחים ב-.doc/glossary.md
  • מילוי שדות חסרים בקטלוג ובקובץ ה-notes
  • מסירה ל-DB Agent להרצת npm run rag:chunks:backfill אחרי כל שינוי תוכן

קבצים: server/db/content/, composables/treatment-catalog/, pages/faq.vue, pages/about.vue

SEO / GEO Agent עדיפות 2נבנה · #10

למה: תוכנית .plan/005-2026-08-17-seo-geo-optimization.md הקימה תשתית (JSON-LD, sitemap, useSeoMeta), אבל אין מי שמתחזק אותה. כל דף טיפול חדש צריך meta, canonical, סכמת MedicalService, קישורים פנימיים ומילות מפתח בעברית ("בוטוקס כפר סבא", "טיפול בהזעת יתר").

תחומי אחריות:

  • ביקורת meta/OG/canonical על כל דף
  • תחזוקת composables/useSchemaOrg.ts ו-JSON-LD לפי סוג דף
  • וידוא שדפי טיפול חדשים נכנסים ל-server/api/_sitemap-urls.get.ts
  • אסטרטגיית מילות מפתח ו-GEO (AI Overviews, Perplexity, ChatGPT Search)
  • בעתיד: Search Console דרך MCP

כלים: read, edit, search

Analytics & Campaign Agent — GTM / GA4 עדיפות 2נבנה · #11

למה: שרת ה-MCP (chenIntegrations) כבר חושף כלי כתיבה ל-GTM (gtm_create_tag, gtm_create_trigger, gtm_create_variable, gtm_deploy_version_to_environment) ודוחות GA4 (ga4_run_report) — ואף Agent לא משתמש בהם. דף הקמפיין pages/lp/instagram-botox.vue הוא שלד בלי UTM ובלי אירועי המרה. ה-KPIs ב-.doc/product-definition.md (CTA CTR, השלמת טופס, bounce) לא נמדדים.

תחומי אחריות:

  • הגדרת אירועי dataLayer ב-plugins/analytics.client.ts (CTA click, form submit, video play, chat open)
  • יצירת tags / triggers / variables ב-GTM ופריסה לסביבות dev/prod
  • דוחות GA4 שבועיים מול יעדי ה-KPI
  • בניית variants לדפי LP ממומנים עם לכידת UTM

כלים: read, edit, MCP tools (ga4_*, gtm_*)

RAG Quality Agent — איכות הצ'אט עדיפות 3נבנה · #12

למה: ב-server/rag/chat-retrieval-rules.ts יש רק 4 חוקים (profile, location, consultation, hyperhidrosis). אין כיסוי ל-botox, morpheus ולכל קטגוריית skin-quality (PRP, רדיאס היברידי, מזותרפיה, פילינג רפואי, skin-booster). ה-Backend Agent עסוק בקוד, לא ב"האם הצ'אט עונה נכון".

תחומי אחריות:

  • סט שאלות בדיקה בעברית (golden set) ובדיקות רגרסיה על התשובות
  • הוספת retrieval rules לטיפולים ולקטגוריות חדשות
  • בדיקת הזיות מול ה-CONTEXT ווידוא שהמודל אומר "לא מופיע באתר" כשצריך
  • וידוא שה-CHAT_REPLY_DISCLAIMER לא נמחק (דרישת compliance)
  • כוונון similarityBase / retrievalTopK

קבצים: server/rag/, server/api/chat.post.ts, server/db/backfill-content-chunks.ts

Compliance & Accessibility Reviewer — קריאה בלבד עדיפות 1נבנה · #9

למה: אתר רפואי בישראל כפוף לכללי פרסום רופאים (משרד הבריאות) ולחוק שוויון זכויות לאנשים עם מוגבלות — תקן 5568 / WCAG 2.0 AA. זו חובה חוקית עם חשיפה לתביעות. ה-QA Agent בודק build וסקיוריטי, לא את זה.

תחומי אחריות:

  • סריקת ניסוחים בעייתיים ("תוצאות מובטחות", "ללא סיכון", "הטוב בישראל")
  • וידוא דיסקליימרים רפואיים בדפי טיפול ובצ'אט
  • alt לכל תמונה, aria-label בעברית, ניווט מקלדת, focus states
  • ניגודיות צבעים בפלטה — Soft Sand #E5D8C5 על Ivory #F5F3EA עלול להיכשל ב-AA
  • הצהרת נגישות (דף חובה)
  • פולט PASS / FAIL מובנה כמו QA Agent, ומשתלב ב-loopback של ה-Orchestrator

כלים: read, search בלבד (לא עורך קבצים)

Release / Ops Agent שלב ב'נבנה · #13

4. סדר ההפעלה החדש ב-Orchestrator

DB → Backend → Frontend → (on-demand: Content / SEO / Analytics / RAG Quality / Release-Ops) → Backend Security → Frontend Security → Compliance & Accessibility → QA

סוקרים פולטים PASS / FAIL. ממצאי Medium ומעלה חוסמים ומחזירים ל-agent המבצע; Low הם advisories בלבד. תקציב ה-loopback נשאר 3 ניסיונות ל-issue.

5. הערות ופעולות נלוות

כפילות: כל Agent קיים מופיע פעמיים ברשימת ה-Agents הזמינים — כנראה נרשם משני מקומות. שווה לבדוק שאין כפילות ב-config של VS Code / Copilot.
עודכנו: agents: ב-orchestrator.agent.md, טבלת "Multi-Agent Team" ב-.github/AGENTS.md (13 agents), וסעיף "Cross-cutting Domain Awareness" ב-Orchestrator.
ממצאי אבטחה פתוחים שה-Security Agents ידווחו כ-Medium עד שייפתרו בתוכניות המשך: CSRF על /api/chat, zod ב-chat route, RLS על match_treatment_content(), security headers, כלי MCP כותבים.
